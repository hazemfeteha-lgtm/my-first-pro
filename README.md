# خدمات مصر — نظام إدارة ومتابعة المركز

برنامج سطح مكتب (Windows) لإدارة مركز خدمات مصر — الإسكندرية: العاملون، الحضور والانصراف،
زيارات المركز، الصيانة، الجرد (نظافة / ورقي / أحبار)، المشتريات، ملاحظات وأخطاء العاملين،
التقارير والطباعة. يعمل **بدون إنترنت**، وقاعدة البيانات محلية (SQLite).

- **تصميم وتطوير:** حازم فتيحه
- **الإصدار:** 2.4.0
- **اللغة:** عربي / إنجليزي (زر التبديل داخل البرنامج)
- **للمطورين:** ملف **`التطوير.md`** فيه آخر نقطة توقف وخريطة كل دالة فين وخطة التحديث القادم — وعلامة **«نقطة نهاية آخر تحديث»** في نهاية `center_management.py`.

## الجديد في 2.4.0

- **تشغيل البرنامج على أكثر من جهاز (شبكة LAN):** جهاز واحد «رئيسي (سيرفر)» يملك قاعدة البيانات، وباقي الأجهزة «محطات» (الأمن / الاستقبال / الصيانة) تشتغل بنفس البرنامج وتبعث كل البيانات للجهاز الرئيسي. كل المحطات تشوف نفس البيانات لحظيًا.
- **باسورد محدود لكل محطة:** مثلاً محطة الأمن تدخل باسم مستخدم صلاحياته «حضور + جهات + صيانة» فقط، والباقي ممنوع — والفحص يتم **على الجهاز الرئيسي** نفسه، فمافيش محطة تقدر تتحايل.
- **سجل عمليات (Audit):** يبيّن مين أضاف/عدّل/حذف وإيه الجهاز اللي عمل العملية والوقت.
- **تحديث تلقائي للشاشات:** لو جهاز تاني عدّل بيانات، الصفحة بتتحدّث لوحدها (قابل للضبط أو الإيقاف).
- **الصور:** ترفع تلقائيًا للجهاز الرئيسي وتظهر على كل الأجهزة.
- **طابور أوفلاين:** لو الشبكة قطعت لحظة، العمليات بتتخزن وتتبعت لوحدها أول ما الاتصال يرجع.

## الجديد في 2.3.1

- **إصلاح عرض العربي في الجداول والقوائم على لينكس:** خانات الجداول وقيم القوائم المنسدلة بقت تظهر بحروف عربية متصلة وترتيب صحيح (على ويندوز كان سليمًا أصلًا). الإصلاح لا يغيّر أي بيانات — القراءة من الجدول تفضل نصًّا خامًا نظيفًا.

## الجديد في 2.3.0

- **حضور/انصراف بضغطة واحدة:** في صفحة حضور وانصراف العاملين — اختر اسم العامل واضغط «✅ حضور الآن» فيتسجل وقت الحضور من ساعة الجهاز، وبنفس الطريقة لاحقًا «🚪 انصراف الآن» لتسجيل الخروج.
- **تقارير حضور الجهات:** زر «🖨️ طباعة تقارير» في صفحة حضور وانصراف الجهات — بالمدة أو بالجهة أو بالاسم، تفاصيل + ملخصات، طباعة/PDF أو Excel.
- **نوعا تقرير جديدان** في صفحة استخراج وطباعة التقارير: «حضور موظفي الجهات» و«قاعدة موظفي الجهات».
- **الألوان والمظهر:** 7 لوحات نهارية (مؤسسية/حكومية/خضراء/ملكية/تركوازية/رمادية/بيج) + الوضع الليلي، و3 أشكال عرض (مريح / مضغوط / كلاسيكي).

## التشغيل من ملف exe (بدون Python)

نزّل `KhadamatMisr.exe` من تبويب **Actions** في GitHub (أو من `dist/` بعد البناء المحلي)،
وحطه في مجلد خاص به ثم شغّله. أول تشغيل هيطلب منك اختيار كلمة مرور لحساب `admin`.

> قاعدة البيانات `center_management.db` ومجلد `photos` بيتعملوا **بجوار** الملف التنفيذي،
> فانسخهم مع بعض عند النقل أو أخذ نسخة احتياطية.

## التشغيل من المصدر

```bash
pip install -r requirements.txt
python center_management.py
```

أو على ويندوز: دوس مرتين على `run.bat`.

## بناء نسخة exe

محليًا على ويندوز:

```bat
build_exe.bat
```

أو تلقائيًا عبر GitHub Actions: أي push على `main` أو `khadamat-misr` يشغّل
`.github/workflows/build-windows.yml` ويرفع `KhadamatMisr.exe` كـ Artifact.

## تشغيل أكثر من جهاز على الشبكة (LAN)

الفكرة: جهاز واحد بس هو اللي فيه قاعدة البيانات، والباقي محطات.

1. على **الجهاز الرئيسي**: افتح البرنامج → قائمة المستخدم (فوق) → **🌐 الشبكة (LAN)** → اختر
   **«جهاز رئيسي / سيرفر»** → اضغط **🔑 توليد كلمة ربط** → **حفظ**، وبعدين أعد تشغيل البرنامج.
2. على **كل محطة**: نفس القائمة → اختر **«محطة»** → اكتب **عنوان الجهاز الرئيسي** (زي `192.168.1.10`)
   و**نفس المنفذ** و**نفس كلمة الربط** → **🔌 اختبار الاتصال** → **حفظ** → أعد التشغيل.
3. سجّل الدخول باسم مستخدم صلاحياته محدودة (مثلاً `security`).

> - لازم الأجهزة كلها على **نفس الشبكة**، والجهاز الرئيسي يفضل مفتوح وقت العمل.
> - اسمح للمنفذ (افتراضيًا **8765**) في **جدار الحماية** على الجهاز الرئيسي.
> - العنوان يظهر تلقائيًا في نافذة الشبكة على الجهاز الرئيسي.
> - الوضع الافتراضي **«مستقل»** — يعني لو مستخدمتش الشبكة، كل حاجة زي ما هي على جهاز واحد.
> - من سطر الأوامر (اختياري): `KhadamatMisr.exe --server` أو `KhadamatMisr.exe --client 192.168.1.10 --token xxxx`.

## الأمان

- لا توجد كلمة مرور افتراضية داخل الكود: أول تشغيل يطلب اختيار كلمة مرور (6 أحرف على الأقل).
- كلمات المرور: PBKDF2-SHA256 (120,000 تكرار) + مِلح عشوائي لكل مستخدم.
- أسماء الجداول/الأعمدة في SQL متحققة قبل الاستخدام (حماية من الحقن).
- كل خطأ غير متوقع يُسجَّل في `crash.log` بجوار البرنامج.
- **الشبكة:** كل محطة لازمها **كلمة ربط (Token)** يطلعها الجهاز الرئيسي، وصلاحيات كل مستخدم تُفحص
  على الجهاز الرئيسي قبل تنفيذ أي عملية، وكل إضافة/تعديل/حذف تتسجل في سجل العمليات.
- **لا تُرفع** `center_management.db` ولا مجلد `photos` على GitHub (بيانات شخصية) — مستثناة في `.gitignore`،
  وكذلك `net_settings.json` (فيه كلمة الربط) وملفات النسخ الاحتياطي.
